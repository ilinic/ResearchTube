# Reliability and durable research recovery

## Upgrade
Update Agent 2.8.20 and Extension 2.11.30 together (interface 97), rebuild Extension, deploy Worker 0.2.13 with generated catalog and validators, then refresh MCP. Existing Workspace and research database are preserved. Never remove database/WAL/SHM files during upgrade or rollback. The old db_sql tool is removed, without an alias. Mixed Agent/Extension versions are intentionally rejected. No migration of existing research tables is required.

## Durable SQL
Use a unique stable operationId per collected logical package. Submit via db_outbox_submit({operationId,sql}); only a confirmed submission means the payload is durably accepted. Poll db_outbox_status; when committed, reconcile research counts and call db_outbox_ack. db_outbox_list gives pending/unknown/failed/unacknowledged packages without SQL payload. Acknowledgement removes the payload only, not its deduplication ledger entry. Exact same key and SQL returns existing state; changed payload under that key is rejected. Failed-permanent packages are retained for inspection and manual correction using a new key. No automatic deletion of uncommitted work. The outbox is protected in the same SQLite database, and commit/ledger/outbox state change is atomic. If database admission itself fails, retain the source data: the Agent cannot recover a request it never durably accepted. Restart recovery processes pending, processing and unknown packages, checking the ledger before execution. There is one FIFO for outbox operations. db_query opens separate mode=ro connections with query_only and a read-only authorizer; up to eight concurrent queries by default (sqlReadConcurrency 1–16), bounded admission of 256. Default queue 4096, wait 12 seconds; execution budget 8 seconds. Outbox logical payload quota 64 MiB (configurable 1–256), 10,000 packages. The ledger has its independent logical 64 MiB/100,000-key cap; it is not automatically evicted, so old keys cannot silently become replayable. Backpressure requires maintenance/reconciliation; do not delete keys casually. This is a logical quota, not a guarantee of SQLite physical file size. There is no public direct write path; all schema/data changes must be submitted through the durable outbox.

## Diagnostics
system_get_trace({limit:20,includeSummary:true}) gives paginated recent events and component/tool counts, percentiles, retries and queue depth. Filter by requestId, component, tool, code, level, sinceMs, tabId/chatTabId/groupId/taskId. A requestId report identifies the latest retained stage, observed stages and known execution state; missing stages remain unknown, and the report covers the retained page, not proof of ChatGPT receipt. Use nextCursor for older events. On explicit user request, system_export_trace creates/replaces the single reserved Workspace file scheduled/reliability-trace.jsonl, up to 4 MiB, with the same filters. It expires automatically. Do not use it as persistent research storage. No SQL payload, page text, token or URL is included in the new technical trace.

Default retention 3600s; disk budget 64 MiB including one export and its temporary replacement (56 MiB journal). The Agent is the writer; events are batched every ~30 seconds or earlier under pressure/error. 16 MiB serialized buffer budget and event count limits are not measured process RSS. Config: reliabilityRetentionSeconds (60–86400), reliabilityDiskMiB (16–64), sqlOutboxMiB and sqlQueueCapacity. Older data may disappear early under pressure. Recent unflushed events may be lost on unexpected worker termination. Disk failures must not stop other tools. Existing legacy diagnostics are separate. Worker OAuth failures before extension dispatch are not present in the local trace; use Cloudflare console inspection. Cloud retention is platform-managed, not the local hour quota.

## Recovery
SQLite WAL/FULL with atomic transactions and bounded busy/locked retry. The Extension retries only classified transport failures within a deadline, and only for safe reads, stable-key writes or failure before dispatch. Site reads with no nodeId may recover once after a transient CDP failure, with fresh authorization/group checks and no active file task on the tab. Never replay a click/send, never use stale node IDs. Scheduler logs tick and per-tab decision; unknown Send remains guarded by existing reservation logic. Local bridge reconnects without replay. Temporary OAuth verification errors return 503 without invalid_token challenge. Genuine expiry/revocation may still require reconnect.

## MCP payload size telemetry
`system_get_trace({includePayloadSummary:true,limit:1})` reports totals for the retained interval and up to 100 conversation/tool groups, largest result payload first. Optional `conversationId` filters a verified conversation (the saved chat ID, not a transient tab ID); no source is guessed for calls without verified context. Such calls are counted separately as unattributed. Raw event `MCP_PAYLOAD_SIZE` records UTF-8 argument JSON bytes, result JSON bytes, text content bytes, structured JSON bytes, byte count of exact duplicate JSON text, actual outgoing relay frame bytes and whether the relay substituted a size-limit error. `PLAN_PROMPT_SIZE` measures confirmed scheduler/handoff prompts. Count each terminal request sample once across RAM, disk and retransmitted trace batches. Result, text and structured sizes overlap; do not add them as independent payloads. Relay delivery is not proof of OpenAI receipt or model token use. The report covers only retained samples, may be incomplete after failures or eviction, and includes no actual arguments, page contents, SQL, prompt text or tokens. Model context length cannot be inferred exactly from UTF-8 byte counts. Retention defaults to one hour and may be set up to one day; the existing RAM/disk safety ceilings remain. Public cloud MCP now removes exact duplicate JSON text blocks before the relay; the complete structuredContent remains authoritative. If no independent content remains, a short text marker points to structuredContent. Widget metadata, errors, independent text and media remain unchanged. Local Codex MCP retains its previous compatibility format. MCP_DUPLICATE_REMOVED records the actual result JSON byte savings; MCP_PAYLOAD_SIZE measures the compacted response. This deliberately departs from the recommended duplicate text fallback and must be verified in live ChatGPT. Browser observations omit empty childIds/resources and zero childCount/false truncated; missing values mean the corresponding defaults. Nonempty references and true truncation remain. No text or pagination budget was reduced.

## Repeated results and context savings
Public cloud MCP uses a bounded in-memory SHA-256 cache of previously forwarded read results, scoped to the verified conversation and Chrome document. It stores hashes, timestamps and prior request IDs, not payload bodies. The cache expires after one hour and holds up to 4096 entries. Selected reads (db_query, workspace_read_text, memory_read, plan_read, agent_memory_read/history, skill_list/read/history) are still executed against current data. Large byte-identical results can return unchanged=true, resultHash and previousRequestId instead of full contents. force_full=true restores a full result, including bypassing known_version. No mutation, task status, error, widget, or unbound call is suppressed. A new conversation/document starts fresh; forwarding is not proof the model still remembers data. Local Codex retains full responses by default. Trace payloadSummary reports repeatHits/repeatSavedBytes, duplicateHits/duplicateSavedBytes and contextHits/contextSavedBytes. Values are transport bytes, not token counts. No persistent cache or additional database.
