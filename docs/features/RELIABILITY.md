# Reliability diagnostics (Agent 2.8.10 / Extension 2.11.20 / Worker 0.2.4)
  
The current implementation keeps one rolling hour of technical events, including successes and failures. The Agent is the sole diagnostic disk owner: `reliability-trace/trace-*.jsonl` alongside the Agent, 64 MiB total, 4 MiB segments, rotation also after five minutes; 16 MiB/25,000 events per process buffer. A background writer flushes every ~30 seconds or sooner on errors or threshold. Oldest data may disappear sooner under pressure. No SQL payloads, page/chat text, secrets or URLs in the new trace. Existing legacy diagnostics are distinct. Recent unflushed events can disappear on worker termination; no business data is stored in the trace.

Use `system_get_trace({limit:20,includeSummary:true})`, then filter by requestId, component, tool, code, level, sinceMs, tabId/chatTabId/groupId/taskId or paginate with nextCursor. Summary is per component/tool (not cross-layer unique operation counts); p50/p95/p99 use retained successful completion samples. A sent response is evidence of transfer to the next controlled layer, not of ChatGPT receiving it. Cloud OAuth failures before extension dispatch cannot be observed in the local trace; the Worker emits safe OAuth status events to console for live Cloudflare inspection. Cloud log retention is platform-managed, not the local hour quota.

All db_sql batches currently use a single FIFO (including reads, avoiding unreliable SQL-prefix classification), default 4096 admitted, configurable sqlQueueCapacity 1–16384, queue wait 12 seconds, execution budget 8 seconds. SQLite WAL, FULL synchronous, foreign keys remain enabled; busy/locked retries limited to 3 with jitter and confirmed rollback/not-started. Explicit operationId is optional for legacy clients. Repeat the exact same payload and key to retrieve the committed result without a second write. Keep the key with the research package. The protected internal ledger is atomic with the SQL transaction, capped at 64 MiB logical payload/100,000 keys; there is no automatic eviction of keys (explicit DB_DEDUP_FULL instead of silently losing deduplication). Plan ledger maintenance before its quota fills. Never delete the live database or its WAL/SHM files.

OAuth access-token TTL is 3600 seconds, with refresh grant retained. Unknown verifier errors return 503 without invalid_token challenge. Real authorization failures still require consent/reconnect. The local bridge reconnects with bounded backoff; it does not replay uncertain actions.

Install/rebuild Extension and Agent, deploy Worker with its existing generated catalog/validators, refresh ChatGPT MCP tools. Existing research tables and Workspace are preserved. For rollback, revert code/builds only, keep the database including the internal operation ledger. Do not run old clients with idempotency assumptions until all components are upgraded.

Remaining work: durable pending outbox/restart replay, a bounded Workspace export, richer CDP error messages and read recovery, transport-wide instrumentation for all non-memory local Agent HTTP routes, Cloudflare refresh-token concurrency/load tests, and a measured 30–60 minute performance/fault-injection run. The primary cause of intermittent tool failures is not yet proven. No changes were made to ChatGPT's OAuth client.
